# МебельСофия — интернет-магазин мебели

Учебное веб-приложение: витрина мебельного магазина с каталогом, корзиной, заказами, регистрацией и авторизацией.

- **Backend**: Python 3.12+, FastAPI, Uvicorn, SQLite, PyJWT
- **Frontend**: классический HTML + CSS + JavaScript (без фреймворков и сборки)

---

## Быстрый старт

### Вариант 1 — всё на Python (рекомендуется для разработки)

```bash
cd backend
./venv/bin/python main.py          # Windows: venv\Scripts\python main.py
```

Откройте **http://localhost:8443** — бэкенд сам раздаёт `frontend/`,
API и сайт на одном порту.

### Вариант 2 — Docker

```bash
docker compose up --build          # из корня проекта
```

Настройки контейнера заданы в `docker-compose.yml`: том `db-data`
сохраняет базу между перезапусками, `frontend/` монтируется в контейнер.

### Вариант 3 — раздельно

```bash
cd backend && ./venv/bin/python main.py     # API на 8443
cd frontend && python3 -m http.server 8080  # сайт на 8080
```

Фронт сам определит, что бэкенд на другом порту, и пойдёт на
`http://localhost:8443` (CORS разрешён для всех источников).

### Первый запуск

1. Откройте «Регистрация» и создайте аккаунт (логин 3–32 символа, пароль 6–64).
2. После регистрации вы сразу входите в магазин.
3. Добавьте товары в корзину → «Оформить заказ» — заказ сохранится в БД
   и появится в профиле.

## API

Формат: JSON. Базовый адрес: `http://localhost:8443`.
Авторизация — заголовок `Authorization: Bearer <jwt>`.

### Аутентификация

| Метод | Путь | Описание |
|---|---|---|
| `PUT /user` | Регистрация. Тело: `{login, password}` → `201 {status, login}`. Ошибки: `409` «такой логин уже занят», `422` — валидация |
| `POST /login` | `{login, password}` → `{token, login}`. `401` при неверных данных |
| `POST /valid_jwt` | `{token}` → `true` / `false` (включает проверку срока действия) |

### Товары (без авторизации)

| Метод | Путь | Описание |
|---|---|---|
| `GET /products` | Все товары. Параметр `?category=living/bedroom/kitchen/office/hallway` |
| `GET /products/{id}` | Один товар. `404`, если нет |

Товар: `id, category, title, price, image, rating, material, color, dimensions, description`.

### Заказы (только с JWT)

| Метод | Путь | Описание |
|---|---|---|
| `POST /orders` | Тело: `{"items": [{"id", "qty"}]}` → `201` с расчётом суммы по ценам из БД. `401` без токена, `401` «expired/invalid», `400` если товара нет |
| `GET /orders` | История заказов текущего пользователя (ботам чужую историю не показывает — id берётся из токена) |

### Профиль

| Метод | Путь | Описание |
|---|---|---|
| `POST /user` | `{login, password, new_password}` — смена пароля (`401`, если текущий неверен) |
| `DELETE /user` | `{login, password}` — удаление аккаунта вместе с заказами (`401`, если пароль неверен) |

### Примеры curl

```bash
# Регистрация
curl -X PUT http://localhost:8443/user \
     -H "Content-Type: application/json" \
     -d '{"login":"anna","password":"secret123"}'

# Вход
TOKEN=$(curl -s -X POST http://localhost:8443/login \
     -H "Content-Type: application/json" \
     -d '{"login":"anna","password":"secret123"}' \
     | python3 -c "import json,sys; print(json.load(sys.stdin)['token'])")

# Каталог
curl http://localhost:8443/products

# Заказ
curl -X POST http://localhost:8443/orders \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"items":[{"id":5,"qty":1}]}'

# История заказов
curl http://localhost:8443/orders -H "Authorization: Bearer $TOKEN"
```

Интерактивная документация Swagger: `http://localhost:8443/docs`.

## Схема базы данных (SQLite)

```
users                 products (наполняется сидом)      orders
─────                 ───────────────────────────       ──────
id INTEGER PK         id INTEGER PK                     id INTEGER PK AI
login UNIQUE          category TEXT                      user_id → users.id
password TEXT          title TEXT                        total INTEGER
password_hash TEXT     price INTEGER                     items JSON
                       rating REAL                       created_at TEXT
                       ... описание, материал и т.д.
```

- **Пароли**: `PBKDF2-SHA256`, 100 000 итераций, случайная соль,
  хранятся как `salt$digest` (`backend/security.py`). Пароли старой версии
  базы мигрируют в хеши при первом запуске, данные пользователей сохраняются.
- **Заказы**: `items` — снимок позиций (`id, title, price, qty`) на момент
  оформления, сумма считается сервером.

## Авторизация на сайте

1. Форма входа отправляет `POST /login`, JWT сохраняется в
   `localStorage` (ключ `jwt`), логин — ключ `login`.
2. Все защищённые запросы (корзина → `POST /orders`, профиль → `GET /orders`
   и т.д.) идут через `apiFetch()` из `frontend/util.js` с заголовком
   Authorization: Bearer.
3. При открытии страницы проверяется `POST /valid_jwt`;
   при истёкшем/невалидном токене — редирект на `login.html`.
4. Корзина хранится в `localStorage` (ключ `cart`) как `[{id, qty}]` —
   цены всегда загружаются из БД, а не из локального снапшота.

## Frontend-страницы

| Страница | Что делает |
|---|---|
| `index.html` | Баннер + каталог: фильтр по 5 категориям, поиск, сортировка (по цене, рейтингу, популярности), ленивые картинки |
| `product.html` | Карточка товара: описание, характеристики, добавление в корзину |
| `cart.html` | Управление количеством, удаление, итог, оформление заказа через `POST /orders` |
| `profile.html` | Логин, смена пароля, история заказов из БД, выход, удаление аккаунта |
| `login.html` / `register.html` | Аутентификация, с осмысленными сообщениями об ошибках на русском (в т.ч. для 422-валидации) |

Состояния страниц (загрузка / ошибка «повторить» / «товар не найден») обработаны — пустых экранов нет.

Плейсхолдеры лежат в `frontend/images/*.svg` (список соответствий —
в `frontend/images/README.md`). Положите свои файлы с теми же именами

и пересоздайте базу. Рекомендация: JPG/WebP 900×675 (4:3).
Отображение не искажает пропорции (`object-fit: cover`).

## Безопасность и ограничения

**Что сделано**
- Пароли хешируются (PBKDF2-SHA256), нигде не хранятся и не логируются открыто.
- JWT подписан HS256, проверяется срок действия (`exp`), вход и создание заказов невозможны без токена; ID пользователя берётся из токена, а не из запроса.
- Валидация входных данных (Pydantic): длины полей, числовые диапазоны, уникальность логина.
- HTTP-статусы по смыслу: 401 / 404 / 409 / 400 / 422.

**Что стоит учитывать**
- Токен живёт в `localStorage` — при XSS-атаке он доступен скриптам. Для прода обычно используют httpOnly-cookie.
- SQLite без пула/блокировок ПОС-уровня — для учебного проекта достаточно, но не для многопользовательской нагрузки.
- Ролевой модели нет: «админка» и управление каталогом (CRUD товаров) отсутствуют.
- `database.db` в `backend/.dockerignore` — в контейнер не копируется
  (база создаётся при старте; в compose — в томе `db-data`).
- `backend/test.py` — черновик-упражнение по классам, к приложению не относится.
